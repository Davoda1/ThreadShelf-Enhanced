# Compatibility contract

ThreadShelf Enhanced 1.2.0 preserves the upstream server contracts and integrates
Reader pagination. The public client reference is [ThreadShelf Local Suite
v1.0.0](https://github.com/Davoda1/ThreadShelf-Local-Suite/tree/v1.0.0), commit
`e17d5874342ce0069acba2ed387d46eefbf61f24`.

| Reference | Scope |
| --- | --- |
| ThreadShelf v1.3.0 | Existing REST routes, MCP, stored turns, path/environment names and continuation behavior |
| Local Suite v1.0.0 Reader and Alternative | Collections, files, threads, Insights, bounded legacy search and Reader v1 cursor API through released HTTP adapters |
| Local Suite v1.0.0 Analytics | Consumes archives published by Local Reader; Enhanced does not generate or migrate the Analytics archive format |
| Supported converted exports | Conversation JSON, `conversations-index.json` and embedded `chat-index.html` data |

Exact public adapter provenance and blob hashes are documented in
[test/fixtures/compatibility-clients/README.md](../test/fixtures/compatibility-clients/README.md).
Those hashes identify only the named adapter files; they do not imply that other
application code is identical. Bundled adapter tests do not launch Electron or
validate desktop installers. See [validation](ENHANCED_VALIDATION.md) for the
current public-source gate.

The 1.2.0 correctness update retains the 1.1.0 dependencies, database format,
embedding model and existing vector dimension. It does not require reimporting
archives, rebuilding indexes or changing client data stores. The original
Enhanced 1.0.0 and 1.1.0 releases remain available.

## Shared-store writes

Server, MCP, importer and search processes use shared operating-system locks for
complete storage mutations. Node's built-in SQLite provides only the lock
coordination; conversation and vector storage remains LanceDB, and the collection
registry retains its existing JSON format. Lock sidecars contain no conversation
records. The operating-system locks release automatically on process termination.
The sidecar files remain and must never be deleted while a writer might still be
running.

Upgrade all processes that share a writable store together, stopping older
processes first. Older releases do not acquire these locks. HTTP clients continue
using the same routes and need no corresponding application update. The locking
contract targets local filesystems with working operating-system file locks;
placing the database on a network filesystem is not a tested deployment mode.

Lock acquisition waits asynchronously and fails explicitly after 30 seconds of
contention; it never continues without ownership. A failed acquisition can be
retried after the other write completes. Malformed or unreadable collection JSON
is now reported as an error and preserved for recovery rather than treated as an
empty registry.

## Stable identity

Existing JSON imports retain v1.3.0 conversation-key rules. Local clients identify
a thread by server URL, collection, `sourceFile` and `conversationKey`: keep the
same URL and paths when moving an installation. ZIP imports use the physical ZIP
as `sourceFile`; its member path prefixes conversation keys to avoid collisions
between files with positional IDs. Source-member identity remains attached to each
stored conversation.

`/api/files` still returns its legacy array. `/api/search` stays bounded at 50.
`/api/reader/capabilities` advertises Reader search version 1, maximum page 50,
keyword/semantic modes, cursor/provider filters, exact totals and a 900-second
snapshot TTL. `/api/reader/search` serves stable cached snapshots; expired cursors
return 410 and changed query parameters return 400. Do not install an external
pagination patch over this fork.

## Preservation

Source imports are read-only. Normalized turns retain message metadata and
source-role/channel identifiers. Conversation raw data is stored separately once
per thread, with source identity and per-conversation provider. Unselected
branches and otherwise undisplayed messages remain available in that raw data.
JavaScript-unsafe integer tokens become exact decimal strings, matching the
Reader's JSON-safe policy; originals retain their original numeric JSON type.
This is semantic preservation, not a byte-for-byte re-export of the input file.

ThreadShelf JSON export includes the original conversation data, source identity
and enriched normalized turns. Markdown export remains a readable textual export.
Local Analytics' source archive format is generated by Local Reader; Enhanced
does not replace that publication format.

New metadata columns are additive. Back up stores before migration. Downgrading
to unmodified v1.3.0 may discard enhanced metadata during reimport; it is not a
lossless downgrade procedure. Future vendor export formats may need a new
adapter. Unsupported rich widgets remain readable source or placeholders.

## Import and media limits

Limits are defined in `src/enhanced-import/vendor/importers.mjs`. JSON is validated
before writes; source records are read incrementally where supported, while
normalized conversations are staged before replacement. Extremely large archives
still need memory proportional to normalized content. Malformed or cancelled
source files do not partially replace their previous archive.

Referenced local images are resolved within the selected export or ZIP, without
extracting arbitrary paths. Only checked PNG/JPEG/GIF/WebP data is retained,
bounded to 5 MiB per image and 32 MiB total per source. Missing attachments remain
placeholders; a remote URL is loaded only when clicked. Filesystem paths are not
served as arbitrary web resources.

## Known limitations

- A ZIP containing both `conversations.json` and `chat.html` imports both
  representations and can create duplicate conversations. Use one conversation
  representation per import.
- Browser folder uploads filter out image companion files. Use a server-local
  folder or a ZIP containing a single conversation JSON representation and its
  image companions when local assets matter.
- Venice native version 4 backups must be unencrypted. Encrypted Venice backups
  are unsupported.
- JSONL is unsupported; the importer expects a supported JSON document, HTML
  export or ZIP.
- Unknown binary attachments, export-global metadata and unsupported layouts may
  not have a normalized representation. Keep the original export as the complete
  source archive.
